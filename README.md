# نُزُل — منصة حجز فنادق عربية بمعايير عالمية

واجهة React كاملة ببيانات تجريبية + لوحة تحكم + أساس الـ Backend (Node/Express) الجاهز للربط مع **TBO** و **MyFatoorah**.

> الاسم «نُزُل» والألوان مؤقتة — تغييرها في مكان واحد (انظر «تغيير الهوية»).

## التشغيل

```bash
cd client
npm install
npm run dev        # http://localhost:5173
```

لوحة التحكم: صفحة «دخول» ← **دخول تجريبي كمدير** ← `/#/admin`.

تشغيل الـ API (اختياري الآن):

```bash
cd server
npm install
cp .env.example .env
npm run dev        # http://localhost:4000/api/health
```

### تجربة الحجز والدفع الحقيقي (MyFatoorah — بيئة الاختبار)

1. في `server/.env` ضع:
   - `MYFATOORAH_API_KEY=` مفتاح الاختبار العام من صفحة «API Key → Test (Demo) Token» في توثيق MyFatoorah، أو مفتاح حسابك التجريبي.
   - `ADMIN_API_KEY=` أي نص سري من 16 حرفاً فأكثر (مفتاح لوحة التحكم).
2. أنشئ `client/.env` وفيه `VITE_API_URL=http://localhost:4000/api`.
3. شغّل الخادم ثم الواجهة (`npm run dev` في كل مجلد) وافتح `http://localhost:5173`.
4. احجز أي غرفة: ستُحوَّل إلى صفحة MyFatoorah التجريبية؛ ادفع ببطاقة اختبار من صفحة «Test Cards» في توثيقهم، وستعود للموقع والحجز «مؤكد».
5. لوحة التحكم ← «الربط والإعدادات» ← أدخل `ADMIN_API_KEY`: تظهر حجوزات **كل الزوار** القادمة من الخادم.

في هذا الوضع السعر يُحسب في الخادم، والحجوزات تُحفظ في `server/data/bookings.json` (مؤقتاً لحين ربط PostgreSQL).

## ما الذي يعمل الآن

| الجزء | التفاصيل |
|---|---|
| البحث | إكمال تلقائي للوجهات والفنادق (يتجاهل الهمزات والتشكيل)، تقويم مدى تواريخ، ضيوف وغرف |
| النتائج | فلاتر: السعر، النجوم، التقييم، نوع الإقامة، المسافة، المرافق، إلغاء مجاني، إفطار — مع عدّادات، ترتيب، ترقيم صفحات، وكل شيء محفوظ في الرابط |
| الفندق | معرض صور، غرف وأسعار متعددة (وجبات/إلغاء)، تقييمات، تعديل التواريخ والضيوف |
| الحجز | نموذج مع تحقق، أكواد خصم (`NUZUL10`)، طرق دفع MyFatoorah (محاكاة نجاح/فشل)، قسيمة، حجوزاتي وإلغاء |
| عام | عربي RTL افتراضياً + إنجليزي، 7 عملات، مفضلة، متجاوب للجوال |
| لوحة التحكم | نظرة عامة ومبيعات، الحجوزات (بحث/حالة/تصدير CSV)، الفنادق (إظهار/تمييز)، العملاء، **هامش الربح** (عام ولكل وجهة وينعكس فوراً على الموقع)، أكواد الخصم، المدفوعات، الربط |

البيانات: 15 وجهة و150 فندقاً مولّدة في `client/src/data/catalog.js`. الحجوزات والإعدادات تُحفظ في `localStorage` لحين اكتمال الـ Backend.

## تغيير الهوية

- **الألوان**: متغيرات `:root` أعلى `client/src/styles/app.css` (`--brand`, `--accent`, `--bg` …).
- **الاسم والشعار**: `BRAND` و `Logo` في `client/src/components/Layout.jsx`.

## قاعدة البيانات: لماذا PostgreSQL

MySQL يكفي، لكن PostgreSQL أنسب هنا: `JSONB` لحفظ ردود المورّد، PostGIS للبحث على الخريطة، وبحث نصي أقوى. والأهم معمارياً:

- **أسعار وتوافر الفنادق لا تُخزَّن في القاعدة** — تأتي حيّة من TBO وتُحفظ دقائق في **Redis**. هذا سر السرعة.
- القاعدة تحفظ: المستخدمين، الحجوزات، المدفوعات، المحتوى الثابت للفنادق، قواعد الهامش، سجل التدقيق.
- لاحقاً عند كِبر الحجم: Meilisearch/Elasticsearch للإكمال التلقائي.

## الأمان

مطبّق الآن:
- Backend: `helmet`، CORS بقائمة بيضاء، تحديد معدّل الطلبات (أشد على الحجز)، حد لحجم الطلب، `hpp`، تحقق صارم من كل مدخل بـ `zod` (يرفض الحقول الزائدة)، أخطاء بلا تفاصيل داخلية.
- **السعر يُعاد حسابه في الخادم** من المورّد؛ أي سعر يرسله المتصفح يُرفض.
- الدفع بصفحة MyFatoorah المستضافة — بيانات البطاقة لا تمر بخوادمنا. تأكيد الدفع بسؤال MyFatoorah مباشرة لا بثقة المتصفح.
- Frontend: Content‑Security‑Policy، لا `dangerouslySetInnerHTML`، حماية CSV من حقن الصيغ، لا تخزين لكلمات المرور.
- الأسرار في `.env` فقط (مستثنى من Git).

المرحلة القادمة (مع القاعدة): مصادقة argon2id + JWT قصير العمر + refresh token دوّار في كوكي `httpOnly/Secure/SameSite`، حماية CSRF، 2FA إلزامي للإدارة، صلاحيات بالأدوار، سجل تدقيق، التحقق من توقيع webhook، HTTPS + WAF (Cloudflare)، نسخ احتياطي مشفّر.

## خارطة الطريق

1. PostgreSQL + Redis وتطبيق `schema.sql`، والمصادقة الحقيقية وحماية مسارات الإدارة.
2. ربط TBO: استيراد أكواد المدن والفنادق، ثم `Search → PreBook → Book → Cancel` في `providers/tbo.js`.
3. ربط MyFatoorah بمفتاح الاختبار ثم الإنتاج + webhook + الاسترداد.
4. بريد القسيمة (PDF)، خريطة، SEO (SSR عبر Next.js أو prerender لصفحات الوجهات).
5. النشر: الواجهة على CDN، الـ API خلف Nginx/Cloudflare.
